# QICK firmware documentation

One index for everything under `firmware/`. Find what you want to do, open the document next to it.

Documentation is kept in the place where the reader looks for it:

| Kind | Where it lives | Who reads it |
|---|---|---|
| **How to use an IP** | `fusesoc/cores/ip/<ip>/README.md`, next to the IP (template: [IP_README_TEMPLATE](developer/IP_README_TEMPLATE.md)) | whoever uses the IP in a design or from Python |
| **How a project is built and used** | `Top/<board>/<project>/README.md` | whoever builds or runs that project |
| **How a library core works** | the `//!` header of its `.sv` file (TerosHDL reads it; `make rtl-docs` writes it as Markdown) | whoever changes or reuses the RTL |
| **How to work in this repository** | this folder: [user/](user/), [developer/](developer/) | the whole team |

Plans (`PLAN_*.md`) and bring-up logs stay next to the IP they belong to. They are working notes, not documentation.

## Rules for new documents

1. A document about one IP or one project goes **next to it**, not here.
2. A rule is written in **one** place; everything else links to it.
3. A document has one audience. If a section is for another audience, move it to the matching folder.
4. Moving a document: `git mv`, then fix the links (`git grep` the old path). Never leave a copy.
5. Before committing documentation: `make doc-check` (from `firmware/fusesoc/`). It fails on a missing README, a missing template section or a broken link.
6. A new library core is added to the table of its category README (`fusesoc/cores/lib/<category>/README.md`); a new Hog project gets its `README.md`.
