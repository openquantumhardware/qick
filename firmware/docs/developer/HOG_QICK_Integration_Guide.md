# HOG Integration in QICK

Complete guide to integrate [HOG (HDL on Git)](https://cern.ch/hog) into the
QICK repository. Based on real integration experience with
`216/tpv2_std` and `111/tpv1_rfbv1_std`.

---

## What does HOG do for you?

- Embeds the git SHA into the bitstream → total traceability.
- Detects uncommitted files before synthesizing.
- Automatically generates a changelog based on commits.
- Recreates the Vivado project from scratch with a single command.
- Optional: CI/CD with GitLab for automated synthesis.

## Key design decisions (learned from integration)

Understanding these avoids hours of debugging.

**HOG execution order inside `CreateProject`:**
```
1. hog.conf          → HOG reads board/part/tool settings
2. src.src           → HOG adds HDL files
3. ips.src           → HOG adds .xci IP files
4. others.src        → HOG sources additional TCL scripts  ← proj.tcl runs here
5. constraints.con   → HOG adds .xdc files
6. post-creation.tcl → HOG runs this last                  ← set top module here
```

This order has three important consequences:

- `proj.tcl` must **not** call `create_project` — HOG already created it.
- `set_property top` must go in `post-creation.tcl`, not in `proj.tcl`,
  because HOG overrides the top after `others.src` runs.
- HDL modules referenced inside the Block Design (not as IPs but as RTL
  references) are not yet available when the BD TCL runs, because HOG adds
  `src.src` files after `others.src`. See section 3.8 for the fix.

**The BD wrapper** is generated by Vivado into the `.gen/` directory of the
project, not into `Top/`. It must be added from that generated path and never
committed to git — it is regenerated every time.

**HOG only processes committed files.** If a file is not tracked by git,
HOG ignores it silently. Always commit before running `./Hog/Do CREATE`.

## STEP 3 — Add a new project to HOG

Repeat this section for each project. The example uses
`216/tpv2_std` — replace with your project path throughout.

### 3.1 Identify board parameters

Look at the project's `proj.tcl` or `hog.conf` to find:
- `-part` → FPGA part number
- `board_part` → board identifier
- BD TCL filename → tells you the Vivado version

| `216/tpv2_demo` | xczu49dr-ffvf1760-2-e | xilinx.com:zcu216:part0:2.0 | bd_2023-1.tcl |
| `216/tpv1_std` | xczu49dr-ffvf1760-2-e | xilinx.com:zcu216:part0:2.0 | bd_2022-1.tcl |

### 3.2 Create the Top/ directory structure

```bash
cd <repository>/firmware
PROJECT_PATH=216/tpv2_std   # change this for each project

mkdir -p Top/${PROJECT_PATH}/list
```

### 3.3 Create hog.conf

```bash
cat > Top/${PROJECT_PATH}/hog.conf << 'EOF'
# vivado 2023.1

[main]
BOARD_PART=xilinx.com:zcu216:part0:2.0
IP_REPO_PATHS=ip
PART=xczu49dr-ffvf1760-2-e
SIM.USE_IP_COMPILED_LIBS=0
TARGET_LANGUAGE=Verilog
EOF
```

Adjust `BOARD_PART` and `PART` for the target board using the table in 3.1.
Do not add `TOP` here — it is set in `post-creation.tcl`.
A board whose definition is in the repository (RFSoC 4x2) also needs
`BOARD_PART_REPO_PATHS=board_files` before `BOARD_PART`: `pre-creation.tcl` points Vivado
to `board_files/`, the project records the path, and the check below compares it too.

Also declare the run properties the strategies of `proj.tcl` expand to. Hog compares
the project with `hog.conf` before synthesis; any property set in the project but not
declared here makes it set the bitstream's version to 0 and its SHA to the working
tree's. For `Flow_PerfOptimized_high` / `Performance_NetDelay_high`:

```
[synth_1]
STEPS.SYNTH_DESIGN.ARGS.DIRECTIVE=PerformanceOptimized
STEPS.SYNTH_DESIGN.ARGS.FSM_EXTRACTION=one_hot
STEPS.SYNTH_DESIGN.ARGS.KEEP_EQUIVALENT_REGISTERS=1
STEPS.SYNTH_DESIGN.ARGS.NO_LC=1
STEPS.SYNTH_DESIGN.ARGS.RESOURCE_SHARING=off
STEPS.SYNTH_DESIGN.ARGS.SHREG_MIN_SIZE=5

[impl_1]
STEPS.PHYS_OPT_DESIGN.ARGS.DIRECTIVE=AggressiveExplore
STEPS.PLACE_DESIGN.ARGS.DIRECTIVE=ExtraNetDelay_high
STEPS.ROUTE_DESIGN.ARGS.DIRECTIVE=NoTimingRelaxation
```

For other strategies, create the project and let Hog list the differences
(`./Hog/Do CHECKLIST <project>`).

### 3.4 Create proj.tcl

`proj.tcl` is sourced by HOG via `others.src` after the project exists.
Its only jobs are: source the BD TCL, generate the wrapper, and set
synthesis/implementation strategies. It must not call `create_project`.

```bash
cat > Top/${PROJECT_PATH}/proj.tcl << 'EOF'
# Sourced by HOG via others.src after the project is created.
# DO NOT call create_project here — HOG already did it.

set origin_dir [file dirname [info script]]
if { [info exists ::origin_dir_loc] } {
  set origin_dir $::origin_dir_loc
}

# Source the Block Design TCL
source [file normalize "$origin_dir/bd_2023-1.tcl"]

# Generate the BD output products before Hog records the files the scripts
# added; otherwise the wrapper is rewritten and the IPs' .coe appear after the
# record, and Hog sets the bitstream's version to 0.
generate_target all [get_files d_1.bd]

# Generate the BD wrapper — Vivado writes it to the project .gen/ directory
make_wrapper -files [get_files d_1.bd] -top

# Add the wrapper from the Vivado-generated location (not from Top/)
set wrapper [get_files -of_objects [get_filesets sources_1] \
    -filter {NAME =~ "*/d_1/hdl/d_1_wrapper.v"}]
if {$wrapper eq ""} {
    set proj_dir  [get_property DIRECTORY [current_project]]
    set proj_name [get_property NAME      [current_project]]
    set wrapper_path [file normalize \
        "$proj_dir/${proj_name}.gen/sources_1/bd/d_1/hdl/d_1_wrapper.v"]
    add_files -norecurse -fileset [get_filesets sources_1] $wrapper_path
}

# Synthesis and implementation strategies
set_property strategy "Flow_PerfOptimized_high"   [get_runs synth_1]
set_property strategy "Performance_NetDelay_high" [get_runs impl_1]
EOF
```

Adjust the BD TCL filename (`bd_2023-1.tcl`) to match the actual file for
your project.

### 3.5 Create post-creation.tcl

HOG runs this script last, after setting its default top module name.
Use it to override the top with the BD wrapper.

```bash
cat > Top/${PROJECT_PATH}/post-creation.tcl << 'EOF'
# HOG runs this script at the very end of CreateProject,
# after setting its default top module name.
# Override it with the BD wrapper, which is the actual design top.

set_property top "d_1_wrapper" [get_filesets sources_1]
update_compile_order -fileset sources_1
EOF
```

### 3.5b Create pre-creation.tcl and post-bitstream.tcl (traceability)

Two one-line hooks, the same in every project; the work is in `scripts/hog/`.

```bash
cat > Top/${PROJECT_PATH}/pre-creation.tcl << 'EOF'
# HOG runs this script before it creates the project: package the BD's qick:ip IPs
# from the sources of the current commit (see scripts/hog/package_bd_ips.tcl).
set qick_top_dir [file dirname [file normalize [info script]]]
source [file normalize "$qick_top_dir/../../../scripts/hog/package_bd_ips.tcl"]
EOF

cat > Top/${PROJECT_PATH}/post-bitstream.tcl << 'EOF'
# HOG sources this script at the end of its post-bitstream step: copy the BD's .hwh
# next to the bitstream in bin/, with the same name (see scripts/hog/copy_hwh.tcl), and
# write the timing summary of the routed design there (scripts/hog/timing_summary.tcl).
source [file normalize "./scripts/hog/copy_hwh.tcl"]
source [file normalize "./scripts/hog/timing_summary.tcl"]
EOF
```

- `pre-creation.tcl`: `firmware/ip/` is generated and ignored by git. This runs
  `make package` for every `qick:ip` IP the project declares in `qick_ips.txt` (3.5c), so the build
  never uses a package older than the commit.
- `post-bitstream.tcl`: Hog copies the `.bit` into `bin/<group>/<project>-<version>-<SHA>/`
  but not the `.hwh`, which PYNQ needs next to the `.bit` with the same base name. Hog's
  `timing_ok.txt` / `timing_error.txt` has only WNS, TNS, WHS, THS and TPWS; `timing_summary.tcl`
  adds `timing_summary.md` (worst slack of every path group, failing paths grouped by the IP they
  start and end in, Min/Max Skew checks) and `reports/timing_summary_routed.rpt`.

### 3.5c Declare the IPs (`qick_ips.txt`) and name the BD `bd_*.tcl`

Two conventions, the same for every board, so the hooks never have to guess:

* **The block design script is `bd_<something>.tcl`** (`bd_2023-1.tcl`, `bd_2025.2.tcl`, `bd_tpv2_std.tcl`): the name
  `proj.tcl` sources. Hog follows it through `list/others.src`.
* **The qick:ip IPs a project uses are declared in `Top/<group>/<project>/qick_ips.txt`**, one name per line, `#` for
  comments. This file is the single source of what `pre-creation.tcl` packages and what `list/qick_ip_rtl.src` /
  `list/qick_ip_xdc.con` follow. Write it once with
  `python3 scripts/hog/gen_qick_ip_lists.py --init <group>/<project>`, then
  `make -C fusesoc hog-lists PROJ=<group>/<project>` and commit the three files.

The BD must name each qick:ip by its literal VLNV (`qick:ip:axis_sg_int4_v2:1.0`), as Vivado exports it. Picking it with a
helper such as `newest_ipdef <name> qick:ip` is refused: pre-creation packages every IP from the commit's sources, so there is
exactly one version, the commit's. A helper is still fine for IPs that are not qick:ip (e.g. Xilinx's `vrf_data_converter`,
whose catalog can hold several versions). The check that ties the two together runs in pre-creation:
a qick:ip the BD instantiates and `qick_ips.txt` does not declare stops the build with a message naming it
(a declared IP that no BD names only warns).

### 3.6 Copy BD TCL and constraint files

```bash
cp path/to/bd_*.tcl   Top/${PROJECT_PATH}/
cp path/to/ios.xdc    Top/${PROJECT_PATH}/
cp path/to/timing.xdc Top/${PROJECT_PATH}/
```

### 3.7 Check that bd_*.tcl ends correctly

The BD TCL must end with `create_root_design ""` and nothing after it.
The original files sometimes have extra lines that add the wrapper or import
constraints — those belong in `proj.tcl`, not in the BD TCL.

```bash
tail -10 Top/${PROJECT_PATH}/bd_*.tcl
```

Remove these lines if present at the end of the BD TCL:
```tcl
# DELETE these if found at the end of bd_*.tcl
make_wrapper -files [get_files ...] -top
add_files -norecurse ...
set_property top ...
import_files -fileset constrs_1 ...
update_compile_order ...
```

The file must end with exactly:
```tcl
create_root_design ""
```

### 3.8 Handle projects with HDL modules referenced in the Block Design

Some QICK projects instantiate plain HDL modules directly inside the Block
Design (not as packaged IPs). Examples: `lo_spi_mux`, `vect2bits_16`.

The BD TCL generated by Vivado includes a check for these modules at creation
time. This check fails under HOG because HOG sourced the BD TCL (via
`others.src`) before adding the HDL files (via `src.src`).

The fix is to disable the module check in the BD TCL:

```bash
# Find the bCheckModules line and set it to 0
sed -i 's/set bCheckModules 1/set bCheckModules 0/' \
    Top/${PROJECT_PATH}/bd_*.tcl

# Verify
grep bCheckModules Top/${PROJECT_PATH}/bd_*.tcl
# Expected output: set bCheckModules 0
```

The modules are still found correctly during synthesis because HOG adds the
HDL files to the project via `src.src` — the check is only an early
validation that is not needed in the HOG flow.

Then list the HDL files in `src.src` so HOG adds them to the project:

```bash
cat > Top/${PROJECT_PATH}/list/src.src << 'EOF'
# HDL modules referenced directly in the Block Design
# Paths relative to firmware/
hdl/lo_spi_mux.v
hdl/vect2bits_16.v
EOF
```

> **Note on file extensions:** Vivado does not allow SystemVerilog files
> (`.sv`) to be used as direct Block Design module references. If your
> modules are written in SystemVerilog, use the `.v` extension — Vivado
> accepts SystemVerilog syntax inside `.v` files.

### 3.9 Create the list files

```bash
# src.src — empty if no HDL modules are referenced in the BD
# (if you have BD-referenced modules, see section 3.8 instead)
cat > Top/${PROJECT_PATH}/list/src.src << 'EOF'
# Empty — d_1_wrapper.v is generated and added in proj.tcl
# Add HDL files here only if they are referenced as modules in the BD
EOF

# ips.src — empty, all IPs live inside the Block Design
cat > Top/${PROJECT_PATH}/list/ips.src << 'EOF'
# Empty — all IPs are instantiated inside the Block Design (bd_*.tcl)
EOF

# others.src — tells HOG to source proj.tcl, and lists the BD so that the version follows it
cat > Top/${PROJECT_PATH}/list/others.src << EOF
# proj.tcl sources the BD and generates the wrapper.
# It runs after HOG creates the project, which is the correct order.
Top/${PROJECT_PATH}/proj.tcl source
# The block design proj.tcl sources: listed (used by no run) so that Hog's version and SHA follow it.
Top/${PROJECT_PATH}/bd_2025.2.tcl nosynth noimpl nosim
EOF

# qick_ip_rtl.src / qick_ip_xdc.con — generated: the RTL/XDC pre-creation packages for the BD's qick:ip IPs
# (run after the BD and pre-creation.tcl exist; pre-creation refuses to build while they are stale)
make -C fusesoc hog-lists PROJ=${PROJECT_PATH}

# constraints.con — xdc files
cat > Top/${PROJECT_PATH}/list/constraints.con << EOF
Top/${PROJECT_PATH}/ios.xdc
Top/${PROJECT_PATH}/timing.xdc
EOF
```

### 3.10 Commit everything

HOG ignores files that are not committed to git. This step is mandatory.

```bash
git ls-files -o --exclude-standard Top/${PROJECT_PATH}          # review: sources only
git ls-files -o --exclude-standard Top/${PROJECT_PATH} | xargs git add --   # explicit files, never the directory
git commit -m "#<issue> Add the ${PROJECT_PATH} project"
```

### 3.11 Create the Vivado project

```bash
cd <repository>/firmware
./Hog/Do CREATE ${PROJECT_PATH}
```

The project is created in `firmware/Projects/<project_name>/`.
Open it in Vivado to verify the BD and top module are correct.

## Daily workflow

```bash
# Clone the repo including HOG submodule
git clone --recursive <url_of_the_repository>
cd <repository>/firmware

# Recreate a Vivado project from scratch
./Hog/Do CREATE 216/tpv2_std

# Open in Vivado and work normally
vivado Projects/tpv2_std/tpv2_std.xpr

# After modifying the BD: export the BD TCL from Vivado
# File → Export → Export Block Design → save to Top/216/tpv2_std/bd_2023-1.tcl
# Then re-apply the bCheckModules fix if needed (section 3.8)

# Commit changes before synthesizing
git add Top/216/tpv2_std/bd_2023-1.tcl
git commit -m "#<issue> Update the BD with the new readout chain"

# Full build: synthesis + implementation + bitstream
# HOG embeds the git SHA into the bitstream automatically
./Hog/Do W 216/tpv2_std
# Bitstream appears in: firmware/bin/
```

> **After re-exporting the BD TCL from Vivado**, always check that
> `bCheckModules` is still 0. Vivado regenerates the TCL with `bCheckModules 1`
> every time you export, so you need to re-apply the fix:
> ```bash
> sed -i 's/set bCheckModules 1/set bCheckModules 0/' \
>     Top/${PROJECT_PATH}/bd_*.tcl
> ```

## Troubleshooting

**"Invalid Top Module" dialog when opening in Vivado**
HOG sets the top to `top_<project_name>` by default. If `post-creation.tcl`
did not run, the top was not overridden. Verify that `post-creation.tcl`
exists and is committed to git — HOG ignores untracked files.

**`proj.tcl` is not executed / "No IPs found"**
HOG only sources files listed in `others.src` if they are committed to git.
Run `git status Top/<project_path>/` and commit any untracked files before
running `./Hog/Do CREATE`.

**"Module not found in project" error during BD creation**
```
ERROR: [BD::TCL 103-2021] The following module(s) are not found: lo_spi_mux
```
This happens when the BD TCL checks for HDL modules before HOG has added
them to the project. Fix: set `bCheckModules 0` in the BD TCL (section 3.8).

**"SystemVerilog not allowed as top file in reference" error**
```
ERROR: [filemgmt 56-195] Reference 'lo_spi_mux' contains top file
'lo_spi_mux.sv' of type SystemVerilog. This type is not allowed.
```
Vivado cannot use `.sv` files as direct Block Design module references.
Rename the file to `.v` — Vivado accepts SystemVerilog syntax inside `.v`.

**"Git working directory not clean" critical warning**
HOG cannot embed a valid SHA if there are uncommitted changes. Commit all
files under `Top/<project_path>/` before running `./Hog/Do W`.

**Tag format warning**
```
WARNING: Repository tag v2.4.1+376 is not in a Hog-compatible format.
```
HOG expects tags formatted as `vMAJOR.MINOR.PATCH` (e.g. `v2.4.376`).
The `+376` suffix is not standard. The build still works but the version
embedded in the bitstream will be 0. Create a compatible tag:
```bash
# Create a HOG-compatible tag pointing to the same commit
git tag -a v2.4.376 $(git rev-parse v2.4.1+376) -m "HOG compatible tag"
git push origin v2.4.376
```

**HOG cannot find my files**
HOG resolves paths relative to `firmware/` (the directory containing `Hog/`).
Make sure all paths in `list/*.src` are correct relative to `firmware/`.

**After re-exporting the BD TCL, bCheckModules is back to 1**
Vivado always regenerates the BD TCL with `bCheckModules 1`. Re-apply the fix
after every export:
```bash
sed -i 's/set bCheckModules 1/set bCheckModules 0/' \
    Top/<project_path>/bd_*.tcl
git add Top/<project_path>/bd_*.tcl
git commit -m "FIX: Disable bCheckModules after BD TCL re-export"
```

## FuseSoC integration

The `fusesoc/` directory is the complementary workflow for IP development and simulation: [../../fusesoc/README.md](../../fusesoc/README.md)
(`make sim`, `make package`, ...). A Top's `pre-creation.tcl` runs `make package` for every `qick:ip` of its block design.
