# PeakRDL Driver Generation

> **In this repository** the drivers in `qick_lib` keep hand-written register maps. They do not import the generated
> `<ip>_regmap_pkg`, `qick/rdl_regs.py` does not exist yet and `qick_lib/qick/rdl_pkgs/` is local output that is not committed,
> so `make driver-check` has nothing to check. What this document says about drivers that read the package, and about the
> drivers of `axis_streamer`, `axis_kidsim_v3` and `xcom`, applies when that work is merged.

This document describes how to generate Python drivers for QICK IP cores
using [PeakRDL](https://peakrdl.readthedocs.io) and SystemRDL.

## Overview

PeakRDL enables a **single source of truth** approach where you define your
IP's register map once in a `.rdl` file and automatically generate:

- **Python**: register-access package (`peakrdl python`) with an in-memory simulator
- **QICK Driver**: Python class (manual or generated) that uses the register package
- **HTML Documentation**: register map docs (`peakrdl html`)
- **SystemVerilog** (OPTIONAL): an AXI4-Lite register block (`peakrdl regblock`)

> **IMPORTANT — two RTL strategies**
>
> There are two ways an IP can implement its AXI register decode, and this
> determines whether you generate SystemVerilog from the RDL:
>
> 1. **Generated regblock (simple register-only IPs)**
>    The RTL register block would be generated by `peakrdl regblock` (via the
>    `--hdl` flag) and instantiated in the IP, with the RDL as the source of
>    truth for both the RTL and the driver. **No IP in this repository does this
>    today**: every IP's `rdl/Makefile` passes only `--python`, and the RTL
>    instantiates the shared `axil_slv` (`axis_constant_iq` included). The RDL is
>    then documentation plus the driver's register model, and it must be kept
>    consistent with the RTL by hand.
>
> 2. **Custom AXI slave (IPs with memory windows / handshakes)**
>    Example: `axis_tprocv1`. The RTL register decode is a hand-written module
>    (`axi_slv_tprocv1`) because the IP needs features `peakrdl regblock` cannot
>    express: a data-memory access window mapped to the upper AXI address
>    space, an exec/exec_ack handshake to a memory arbiter, and SLVERR
>    responses while memory is busy. In this case you must NOT generate RTL
>    from the RDL — the RDL is used ONLY for the Python driver layer and
>    documentation. Pass only `--python` (and optionally `--html`), never
>    `--hdl`, or the generated regblock will conflict with `axi_slv_tprocv1`.
>
> Pick the strategy per IP. The `make new-ip` template defaults to
> `--hdl --python` (strategy 1); edit the IP's `rdl/Makefile` to remove `--hdl`
> if the IP uses a custom AXI slave (strategy 2).

```
cores/ip/<ip_name>/
├── rdl/
│   ├── <ip_name>_regmap.rdl          ← SOURCE OF TRUTH (you edit this)
│   ├── <ip_name>_regmap.core
│   ├── Makefile
│   ├── <ip_name>_regmap_pkg/         ← Generated Python package (gitignored)
│   └── docs/                         ← Generated HTML docs (gitignored)
├── driver/
│   ├── <ip_name>.py                  ← QICK driver (symlinked to qick_lib/)
│   └── tests/                        ← Python register-layer tests (pytest)
│       ├── conftest.py
│       └── test_<ip_name>_regs.py
├── hdl/
│   └── <ip_name>.sv
└── tests/                            ← SVUnit RTL testbenches (plural, repo-wide)
    ├── <ip_name>_tc00.sv
    └── <ip_name>_tests.sv
```

> Note the two `tests/` locations: `driver/tests/` holds the Python
> register-layer tests (pytest, run by `make driver-test`), while the top-level
> `tests/` holds the SVUnit RTL testbenches (run by `make sim` / `make
> sim_svunit`).

## How It Works on the RFSoC Board

When you run `make driver IP=<ip_name>`:

1. The PeakRDL package is generated in
   `cores/ip/<ip_name>/rdl/<ip_name>_regmap_pkg/` (with `PYTHONHASHSEED=0`, because
   PeakRDL puts Python's randomised `hash()` in its class names; without it every
   regeneration would differ).
2. If the driver is a standalone file (`driver/<ip_name>.py` is a real file, not a
   symlink into one of the monolithic `qick_lib` modules), it is **symlinked** to
   `qick_lib/qick/drivers/<ip_name>.py`. `QickSoc` imports every standalone module
   it finds there, so this symlink is what makes PYNQ bind the driver.
3. The package is **copied** to `qick_lib/qick/rdl_pkgs/<ip_name>_regmap_pkg/`, where
   the driver finds it on the board.
4. `make driver-test` runs automatically (register-layer pytest).
5. (Optional) HTML documentation is generated with `make rdl-docs`.

The symlink and the runtime part of `rdl_pkgs/<ip_name>_regmap_pkg/` (everything except
PeakRDL's own `tests/` and `lib_test/`) are **committed**, so that a plain `git clone`
of the repository on the board works. See [BOARD_WORKFLOW.md](../user/BOARD_WORKFLOW.md) for the
whole flow. `make driver-check IP=<ip_name>` fails if the committed package no longer
matches the RDL.

If your driver imports the generated package, it can search multiple locations
so it works both in development and on the board:

```python
_RDL_PKG_PATHS = [
    Path(__file__).parent.parent / "rdl",        # dev: next to driver
    Path(__file__).parent.parent / "rdl_pkgs",   # prod: installed with QICK
]
```

The classes in the monolithic modules (`tproc.py`, `peripherals.py`, `generator.py`, `readout.py`) do not search paths: they use
`qick/rdl_regs.py`. A class sets `RDL_IP` and `REGISTER_NAMES` (attribute used by the software -> register of the RDL, an array
element as `pinc_regfile[3]`) and calls `_init_regmap(description)` from `_init_config()`. `REGISTERS` then comes from the RDL
addresses and `regs` is the register model for field access.

- A class for a legacy-only IP (no RDL, e.g. `AxisSgInt4V1`, `AxisAvgBuffer` 1.0) keeps its dictionary and has no `regs`.
- `regs` describes the fusesoc IP and warns once on a block whose VLNV is not `qick:ip:`, where some registers differ.
- `make driver-check IP=<ip>` says "nothing to check" if the driver does not use the package; `make driver-test IP=<ip>`
  generates the package under `rdl/` when it is missing.

## Quick Start

### For an existing IP

```bash
cd firmware/fusesoc
source ../../.venv/bin/activate

# Generate the driver layer (RDL -> Python package + QICK symlink + reg tests)
make driver IP=axis_constant_iq

# Run only the register-layer tests (no regeneration)
make driver-test IP=axis_constant_iq

# Generate HTML documentation
make rdl-docs IP=axis_constant_iq

# Simulate the RTL (SVUnit)
make sim_svunit IP=axis_constant_iq
```

### Creating a new IP

```bash
cd firmware/fusesoc

# Create IP structure from template
make new-ip IP=my_new_ip

# Edit the RDL to define your registers
vim cores/ip/my_new_ip/rdl/my_new_ip_regmap.rdl

# If this IP uses a CUSTOM AXI slave (not a generated regblock), edit
# cores/ip/my_new_ip/rdl/Makefile and remove --hdl from the gen target.

# Generate the driver layer
make driver IP=my_new_ip

# Generate docs
make rdl-docs IP=my_new_ip
```

## The rdl/Makefile

Each IP's `rdl/Makefile` derives the IP name from the directory and invokes the
generator. The correct form is (recipe lines are TABs):

```makefile
IP_NAME    = $(shell basename $(shell dirname $(CURDIR)))
RDL_FILE   = $(IP_NAME)_regmap.rdl
GEN_SCRIPT = ../../../../generators/systemrdl/rdl_tools.py

gen:
	python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --python   # add --hdl only for regblock IPs
docs:
	python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --html
clean:
	rm -rf $(IP_NAME)_regmap_pkg $(IP_NAME)_regmap*.sv $(IP_NAME)_regmap*.svh

.PHONY: gen docs clean
```

> **CRITICAL — common Makefile bugs (learned the hard way)**
>
> 1. **IP_NAME path depth**: `$(CURDIR)` inside `rdl/` is
>    `.../cores/ip/<IP_NAME>/rdl`. To get `<IP_NAME>` you need exactly ONE
>    `dirname` (rdl -> <IP_NAME>) then `basename`. Using TWO `dirname` calls
>    climbs to `cores/ip` and `basename` returns the literal `ip`, producing
>    a bogus `ip_regmap.rdl`. Use a single `dirname`.
>
> 2. **Recipe lines need TABs**, not spaces. If your editor converts tabs to
>    spaces, Make fails with "missing separator".
>
> 3. **Add a `docs` target** so `make rdl-docs` works (uses `--html`).
>
> 4. **Strategy 2 IPs must drop `--hdl`** from `gen` so the generated regblock
>    does not conflict with the hand-written AXI slave (`axi_slv_tprocv1`).

### Fixing the new-ip template (create_ip.sh)

`scripts/create_ip.sh` writes the per-IP `rdl/Makefile` via a heredoc. Two bugs
were found and fixed there:

1. The heredoc must use a **quoted delimiter** (`<< 'EOF'`) so bash does NOT
   expand `$` — then write `$(...)` literally WITHOUT backslashes. Using an
   unquoted `<< EOF` with a duplicated `RDL_FILE = $(IP_NAME)_regmap.rdl` line
   made bash run command substitution `$(IP_NAME)` (an unknown command),
   producing an empty `RDL_FILE = _regmap.rdl`.
2. TABs in heredocs are fragile. Write a placeholder `@@TAB@@` for recipe-line
   indentation and convert it to a real tab after the heredoc:

```bash
cat > $IP_DIR/rdl/Makefile << 'EOF'
IP_NAME    = $(shell basename $(shell dirname $(CURDIR)))
RDL_FILE   = $(IP_NAME)_regmap.rdl
GEN_SCRIPT = ../../../../generators/systemrdl/rdl_tools.py

gen:
@@TAB@@python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --hdl --python
docs:
@@TAB@@python3 $(GEN_SCRIPT) $(RDL_FILE) --output . --html
clean:
@@TAB@@rm -rf $(IP_NAME)_regmap_pkg $(IP_NAME)_regmap*.sv $(IP_NAME)_regmap*.svh

.PHONY: gen docs clean
EOF
sed -i 's/@@TAB@@/\t/g' $IP_DIR/rdl/Makefile
```

Verify a newly created IP:

```bash
./scripts/create_ip.sh test_dummy
cat -A cores/ip/test_dummy/rdl/Makefile   # expect ^I (tab), no \$, no @@TAB@@
cd cores/ip/test_dummy/rdl && make -n gen # expect: ... test_dummy_regmap.rdl ...
cd - && rm -rf cores/ip/test_dummy
```

## SystemRDL File Format

The `.rdl` file is the single source of truth for your IP's registers.

**Example: `axis_constant_iq_regmap.rdl`** (register-only IP)

```systemrdl
addrmap axis_constant_iq {
    name = "AXIS Constant IQ Registers";
    desc = "Registers for the axis_constant_iq IP core.";
    default regwidth = 32;
    default accesswidth = 32;
    default addressing = compact;

    reg {
        name = "REAL_REG";
        desc = "16-bit I (real) component of the constant output.";
        field { name = "I"; desc = "In-phase component"; sw = rw; hw = r; } I[15:0] = 0;
    } REAL_REG @0x00;

    reg {
        name = "IMAG_REG";
        desc = "16-bit Q (imaginary) component of the constant output.";
        field { name = "Q"; desc = "Quadrature component"; sw = rw; hw = r; } Q[15:0] = 0;
    } IMAG_REG @0x04;

    reg {
        name = "WE_REG";
        desc = "Update strobe: I/Q are latched on a RISING EDGE of WE; it does not clear itself.";
        field { name = "WE"; desc = "Update strobe (edge-sensitive)."; sw = rw; hw = r; swmod; } WE[0:0] = 0;
    } WE_REG @0x08;
};
```

**Example: `axis_signal_gen_v6_regmap.rdl`** (regblock IP with status/control)

The SG-v6 map includes a read-only status flag driven by hardware
(`SATURATING`) and a control bit to clear it (`SAT_CLEAR`) — the software face
of the amplitude-fix saturation.

```systemrdl
addrmap axis_signal_gen_v6 {
    name = "AXIS Signal Generator v6 Registers";
    default regwidth = 32;
    default accesswidth = 32;

    reg { field { desc = "Envelope write start address."; sw = rw; hw = r; }
          START_ADDR[31:0] = 0; } START_ADDR_REG @ 0x00;

    reg { field { desc = "Envelope write enable."; sw = rw; hw = r; }
          WE[0:0] = 0; } WE_REG @ 0x04;

    reg { desc = "Deprecated (rounding-select removed).";
          field { desc = "Deprecated."; sw = rw; hw = r; }
          RNDQ[31:0] = 0; } RNDQ_REG @ 0x08;

    reg { desc = "Status (read-only).";
          field { desc = "Sticky saturation flag: 1 = output clamped to +/-MAXV.";
                  sw = r; hw = w; }
          SATURATING[0:0] = 0; } STATUS_REG @ 0x0C;

    reg { desc = "Control.";
          field { desc = "Write 1 to clear the sticky saturation flag.";
                  sw = rw; hw = r; }
          SAT_CLEAR[0:0] = 0; } CTRL_REG @ 0x10;
};
```

**Example: `axis_tprocv1_regmap.rdl`** (custom AXI slave IP, strategy 2)

For an IP whose RTL decode is a hand-written `axi_slv_tprocv1`, the RDL describes
ONLY the control registers (the register layer the driver/docs need). The
single-access data-memory window (upper AXI address space) is handled by
`axi_slv_tprocv1` in RTL and by the driver in software; it is intentionally NOT
modeled here.

```systemrdl
addrmap axis_tprocv1 {
    name = "axis_tprocv1 Registers";
    desc = "Control registers for the QICK tProcessor V1. The single
            data-memory access window (upper AXI address space) is handled by
            axi_slv_tprocv1 and the manual driver; it is not part of this map.";
    default regwidth = 32;
    default accesswidth = 32;

    reg { field { sw = rw; hw = r; } START_SRC[0:0] = 0; } START_SRC_REG @ 0x00;
    reg { field { sw = rw; hw = r; } START[0:0]     = 0; } START_REG     @ 0x04;
    reg { field { sw = rw; hw = r; } MEM_MODE[0:0]  = 0; } MEM_MODE_REG  @ 0x08;
    reg { field { sw = rw; hw = r; } MEM_START[0:0] = 0; } MEM_START_REG @ 0x0C;
    reg { field { sw = rw; hw = r; } MEM_ADDR[31:0] = 0; } MEM_ADDR_REG  @ 0x10;
    reg { field { sw = rw; hw = r; } MEM_LEN[31:0]  = 0; } MEM_LEN_REG   @ 0x14;
};
```

> NOTE: Do NOT model the data-memory window as `external mem` in the RDL for a
> driver-only flow. `peakrdl regblock` would generate external-memory interface
> ports (strategy 1), and `peakrdl python` would generate memory accessors you
> do not use. Keep the RDL to just the control registers when the driver
> handles memory access manually.

### Common RDL Patterns

Self-clearing strobe:

```systemrdl
field { swmod; } WE[0:0] = 0;
```

Read-only status set by hardware, cleared by a separate control bit
(SG-v6 saturation pattern):

```systemrdl
field { sw = r;  hw = w; } SATURATING[0:0] = 0;   // in STATUS_REG
field { sw = rw; hw = r; } SAT_CLEAR[0:0]  = 0;   // in CTRL_REG
```

Read-only status with write-clear (single register):

```systemrdl
field { sw = rw; hw = w; swmod; onwrite = woclr; } IRQ_FLAG[7:0];
```

Counter with read-clear:

```systemrdl
field { sw = r; hw = r; counter; onread = rclr; } COUNTER[31:0];
```

Arrays of registers:

```systemrdl
reg { field { sw = rw; hw = r; } DATA[31:0]; } CHANNEL[4] @0x10;  // CHANNEL[0..3]
```

## Generated Python Package

After `make driver`, PeakRDL-python (3.1.2) generates a package whose layout is:

```
<ip_name>_regmap_pkg/
├── reg_model/
│   ├── __init__.py            ← exports `RegModel` (clean alias)
│   └── <ip_name>.py           ← register model class (hash-suffixed name + alias)
├── sim/
│   ├── __init__.py            ← exports `Simulator`
│   └── <ip_name>.py           ← <ip_name>_simulator_cls (in-memory model)
├── lib/                       ← runtime classes (NormalCallbackSet, etc.)
├── sim_lib/                   ← simulator helper classes
└── tests/                     ← PeakRDL-generated unit tests (reference!)
    ├── _<ip_name>_sim_test_base.py   ← shows EXACT instantiation pattern
    └── test_sim_<ip_name>.py
```

> **Confirming the generated API**
>
> The class name in `reg_model/<ip_name>.py` may be hash-suffixed, e.g.
> `axis_tprocv1_neg_0x529130c5eb3f85b1_cls`. PeakRDL provides a clean alias at
> the bottom of the file (`axis_tprocv1_cls = ..._cls`) and, more importantly,
> `reg_model/__init__.py` re-exports it as `RegModel`. Always import the clean
> aliases:
>
> ```python
> from <ip_name>_regmap_pkg.reg_model import RegModel
> from <ip_name>_regmap_pkg.sim import Simulator
> from <ip_name>_regmap_pkg.lib import NormalCallbackSet
> ```
>
> The authoritative usage pattern is in
> `tests/_<ip_name>_sim_test_base.py`. Read it before writing your own tests.

### NormalCallbackSet needs FOUR callbacks

In PeakRDL-python 3.1.2 the simulator wiring requires read/write AND their block
variants:

```python
from <ip_name>_regmap_pkg.reg_model import RegModel
from <ip_name>_regmap_pkg.sim import Simulator
from <ip_name>_regmap_pkg.lib import NormalCallbackSet

sim = Simulator(address=0)
model = RegModel(
    callbacks=NormalCallbackSet(
        read_callback=sim.read,
        write_callback=sim.write,
        read_block_callback=sim.read_block,
        write_block_callback=sim.write_block,
    )
)
```

> If you only pass `read_callback` + `write_callback` (older 2-arg pattern), it
> may fail. The 4-callback form matches the generated `_*_sim_test_base.py`.

### Sync vs Async

PeakRDL-python generates BOTH sync and async APIs (note the many `async_*`
modules under `lib/`). The default model (`RegModel`) is the **synchronous**
one, with `.read()` / `.write()`. If you ever import the async classes you must
use `async def` + `await` + `pytest-asyncio`.

### Generated API

```python
model.REAL_REG.I.write(100)       # write field
model.REAL_REG.I.read()           # read field -> 100
model.REAL_REG.write(200)         # write full register
model.REAL_REG.read()             # read full register -> 200
model.REAL_REG.address            # -> 0x00
model.REAL_REG.I.high             # -> 15
model.REAL_REG.I.low              # -> 0
```

## Testing Without Hardware (pytest)

You can test the register layer / driver sequences without an RFSoC board using
the generated simulator. This is exactly what `make driver-test IP=<name>` runs.
Recommended layout:

```
cores/ip/<ip_name>/driver/tests/
├── conftest.py                 ← puts the generated package on sys.path
└── test_<ip_name>_regs.py      ← your pytest tests
```

**conftest.py**

```python
import sys
from pathlib import Path

# driver/tests/ -> ../../rdl/ contains <ip_name>_regmap_pkg/
_RDL_DIR = Path(__file__).resolve().parents[2] / "rdl"
if str(_RDL_DIR) not in sys.path:
    sys.path.insert(0, str(_RDL_DIR))
```

**test_<ip_name>_regs.py** (example for axis_signal_gen_v6)

```python
import pytest
from axis_signal_gen_v6_regmap_pkg.reg_model import RegModel
from axis_signal_gen_v6_regmap_pkg.sim import Simulator
from axis_signal_gen_v6_regmap_pkg.lib import NormalCallbackSet


def make_sim_regs():
    """Register model backed by the in-memory simulator (no hardware)."""
    sim = Simulator(address=0)
    return RegModel(
        callbacks=NormalCallbackSet(
            read_callback=sim.read,
            write_callback=sim.write,
            read_block_callback=sim.read_block,
            write_block_callback=sim.write_block,
        )
    )


@pytest.fixture
def regs():
    return make_sim_regs()


def test_reset_values(regs):
    assert regs.START_ADDR_REG.START_ADDR.read() == 0
    assert regs.WE_REG.WE.read() == 0
    assert regs.STATUS_REG.SATURATING.read() == 0
    assert regs.CTRL_REG.SAT_CLEAR.read() == 0


def test_start_addr_roundtrip(regs):
    regs.START_ADDR_REG.START_ADDR.write(0x1234)
    assert regs.START_ADDR_REG.START_ADDR.read() == 0x1234


def test_load_sequence(regs):
    # Mirrors driver.load(): _wr_enable(addr) -> <DMA> -> _wr_disable()
    addr = 0x40
    regs.START_ADDR_REG.START_ADDR.write(addr)
    regs.WE_REG.WE.write(1)
    assert regs.START_ADDR_REG.START_ADDR.read() == addr
    assert regs.WE_REG.WE.read() == 1
    regs.WE_REG.WE.write(0)          # _wr_disable
    assert regs.WE_REG.WE.read() == 0


def test_saturation_clear_sequence(regs):
    # SATURATING is HW-set (0 in the pure-register sim); exercise the SW path:
    assert regs.STATUS_REG.SATURATING.read() == 0
    regs.CTRL_REG.SAT_CLEAR.write(1)
    assert regs.CTRL_REG.SAT_CLEAR.read() == 1
    regs.CTRL_REG.SAT_CLEAR.write(0)
    assert regs.CTRL_REG.SAT_CLEAR.read() == 0


def test_register_independence(regs):
    regs.START_ADDR_REG.START_ADDR.write(0xABCD)
    regs.WE_REG.WE.write(1)
    regs.CTRL_REG.SAT_CLEAR.write(1)
    assert regs.START_ADDR_REG.START_ADDR.read() == 0xABCD
    assert regs.WE_REG.WE.read() == 1
    assert regs.CTRL_REG.SAT_CLEAR.read() == 1
```

Run:

```bash
make driver-test IP=<ip_name>          # preferred (from firmware/fusesoc/)
# or directly:
pytest cores/ip/<ip_name>/driver/tests/ -v
```

## Writing the QICK Driver

Docstrings describe what each method does. How the IP *behaves* (its rules, formats, limits) is explained once, for
users, in the IP's `README.md` (see [NEW_CORE.md](NEW_CORE.md), section 6); when a method exists because of one of
those rules (`update()` for an edge-sensitive strobe, `set_dead_time()` for the tagger's level comparator), say so in
its docstring in one line and point to the README.

There are two valid driver styles.

### Style A — Manual driver (hardcoded register offsets)

Used by the tProcV1 driver and by the shared arb-generator driver
(`AxisSignalGen`). The driver accesses registers by index via a `REGISTERS`
dict; the generated package is then used for docs / register-layer tests.

```python
class AxisSignalGen(AbsArbSignalGen, AbsPulsedSignalGen):
    # ONE driver binds several IP versions (same SW interface).
    bindto = ['user.org:user:axis_signal_gen_v4:1.0',
              'user.org:user:axis_signal_gen_v5:1.0',
              'user.org:user:axis_signal_gen_v6:1.0',
              'QICK:QICK:axis_signal_gen_v4:1.0',
              'QICK:QICK:axis_signal_gen_v5:1.0',
              'QICK:QICK:axis_signal_gen_v6:1.0']
    MAXV = 2**15 - 2
    REGISTERS = {'start_addr_reg': 0, 'we_reg': 1, 'rndq_reg': 2}

    def _wr_enable(self, addr=0):
        self.start_addr_reg = addr
        self.we_reg = 1

    def _wr_disable(self):
        self.we_reg = 0

    def is_saturating(self):
        return bool(self.status_reg & 1)      # STATUS_REG.SATURATING (amplitude fix)

    def clear_saturation(self):
        self.ctrl_reg = 1                     # CTRL_REG.SAT_CLEAR
        self.ctrl_reg = 0
```

> **Shared driver caveat**: because one `bindto` covers v4/v5/v6, methods like
> `is_saturating()` / `clear_saturation()` run against all of them. Verify the
> older versions actually implement STATUS/CTRL (0x0C/0x10) or guard the calls.
> `rndq()` is deprecated (rounding-select removed by the amplitude fix).

The custom-AXI-slave variant (tProcV1) adds a data-memory window:

```python
class AxisTProc64x32_x8(SocIP):
    bindto = ['user.org:user:axis_tproc64x32_x8:1.0',
              'QICK:QICK:axis_tproc64x32_x8:1.0']
    NREG = 64  # words reserved for registers (256 bytes); DMEM window above
    REGISTERS = {'start_src_reg': 0, 'start_reg': 1,
                 'mem_mode_reg': 2, 'mem_start_reg': 3,
                 'mem_addr_reg': 4, 'mem_len_reg': 5}

    def single_read(self, addr):
        return self.mmio.array[addr + self.NREG]

    def single_write(self, addr=0, data=0):
        self.mmio.array[addr + self.NREG] = np.uint32(data)
```

> The custom AXI slave (`axi_slv_tprocv1`) is REQUIRED for this style: it
> decodes low addresses as registers and high addresses (>= NREG*4) as single
> DMEM accesses with an exec/exec_ack handshake, returning SLVERR while the
> memory arbiter is busy. A generated `peakrdl regblock` cannot do this.

### Style B — Generated-package driver

Used by simple register-only IPs (`axis_constant_iq`). The driver imports the
generated model and accesses fields by name. This is the shape of the real driver
(`cores/ip/axis_constant_iq/driver/axis_constant_iq.py`):

```python
import sys
from pathlib import Path

_RDL_PKG_PATHS = [
    Path(__file__).parent.parent / "rdl",        # dev: next to the driver
    Path(__file__).parent.parent / "rdl_pkgs",   # board: qick_lib/qick/rdl_pkgs
]
for _path in _RDL_PKG_PATHS:
    if (_path / "axis_constant_iq_regmap_pkg").exists():
        if str(_path) not in sys.path:
            sys.path.insert(0, str(_path))
        break

from axis_constant_iq_regmap_pkg.reg_model import RegModel
from axis_constant_iq_regmap_pkg.lib import NormalCallbackSet
from qick.ip import SocIP


class AxisConstantIq(SocIP):
    bindto = ['qick:ip:axis_constant_iq:1.0']       # must equal the VLNV of the packaged IP
    MAXV = 2**15 - 2

    def _init_firmware(self):
        # Called from SocIP.__init__ for both a raw Overlay and QickSoc; only needs self.mmio.
        super()._init_firmware()
        self._reg_model = RegModel(callbacks=NormalCallbackSet(
            read_callback=self._hw_read, write_callback=self._hw_write,
            read_block_callback=self._hw_read_block, write_block_callback=self._hw_write_block))

    def _hw_read(self, addr, width, accesswidth):
        return self.mmio.read(addr)                  # PYNQ's MMIO takes a byte offset

    def _hw_write(self, addr, width, accesswidth, data):
        self.mmio.write(addr, int(data) & 0xFFFFFFFF)

    @property
    def regs(self):
        return self._reg_model

    def update(self):
        # The RTL latches I/Q on a RISING EDGE of WE: pulse it, do not leave it high.
        self.regs.WE_REG.WE.write(1)
        self.regs.WE_REG.WE.write(0)

    def set_iq(self, i=1.0, q=1.0):
        ...   # clip to [-1, 1], scale by MAXV, write REAL_REG/IMAG_REG as unsigned 16 bit, then update()
```

> **Strobe registers.** Check how the RTL consumes a "write enable"/"start" bit before writing
> the driver. `axis_constant_iq` reacts to the *edge* of `WE` (`we_int = ~we_r & we`), so a driver
> or notebook that writes `WE = 1` and leaves it there updates the output only the first time
> (this made a gain sweep look constant during the first hardware bring-up). Expose an
> `update()` that pulses the bit and have the high-level methods call it.

## Using the Driver on Hardware (QickSoc)

> Which class is an IP's driver, where it lives, and what a port needs before it counts as done:
> [IP_INTEGRATION.md](../user/IP_INTEGRATION.md).

`QickSoc` (a PYNQ `Overlay`) binds an IP to a driver class when the IP's **VLNV**
(vendor:library:name:version) matches one of the strings in the class's `bindto`, **and the
class has been imported**. `qick.py` imports the five monolithic driver modules
(`generator`, `readout`, `tproc`, `peripherals`, `xcom`) explicitly, and imports every other
module found in `qick_lib/qick/drivers/` automatically (`_import_ip_drivers()`), skipping alias
symlinks. A standalone driver therefore only needs its symlink in that directory (created by
`make driver`). A driver that fails to import is logged and skipped, so one broken driver does
not take `QickSoc` down; `QickSoc` also warns about every `qick:ip:*` IP that ended up bound to
the generic `DefaultIP`.

Binding is not the same as registration as a QICK channel: `QickSoc` builds `soc.gens`,
`soc.iqs`, `soc.readouts`, ... by driver *class* (`issubclass(..., AbsPulsedSignalGen)` and so
on). A standalone driver such as `AxisConstantIq(SocIP)` is reachable as `soc.<instance_name>`
but is not added to those lists; an IP that must appear there has to subclass the matching
`Abs*` class or `QickSoc` has to be extended.

A firmware without a tProcessor (a debug bench) needs
`QickSoc(bitfile, no_tproc=True)`.

```python
import numpy as np
from qick import QickSoc

soc = QickSoc('my_firmware.bit')
print(soc.ip_dict.keys())          # find your block (name from block design)
gen = soc.gens[0]                  # AxisSignalGen instance

# Low-level envelope load (int16 I/Q via DMA)
n = 1024
env = (gen.MAXV * np.exp(-0.5 * ((np.arange(n) - n/2) / (n/8))**2))
xin = np.zeros((n, 2), dtype=np.int16)
xin[:, 0] = env.astype(np.int16)
gen.load(xin, addr=0)

# Amplitude-fix saturation check
gen.clear_saturation()
# ... play pulses ...
if gen.is_saturating():
    print("SG output clamped to +/-MAXV; reduce gain/envelope.")
```

> **VLNV / bindto MUST MATCH**
>
> The IPs packaged from this repository have VLNV `qick:ip:<name>:<version>`; the legacy
> Vivado IPs are `QICK:QICK:...` / `Fermi:user:...` / `user.org:user:...`. A driver that must
> serve both lists all of them (see `QICK_Time_Tagger` in `peripherals.py`); it can also
> need to pick port names by VLNV, because the fusesoc port renamed some ports.
> If you rename the IP module (e.g. `axis_tproc64x32_x8` -> `axis_tprocv1`), the
> package VLNV and the driver `bindto` can drift apart and QICK will NOT load the
> driver. Either:
>   - keep the IP name (`make package IP=... --ip-name axis_tproc64x32_x8`) so
>     the existing `bindto` matches, OR
>   - update `bindto` to the new VLNV (e.g. `qick:ip:axis_tprocv1:1.0`).
>
> The RTL module name and the IP/VLNV name may differ; what matters for driver
> loading is the VLNV vs `bindto`.

## Signed vs Unsigned Fields

PeakRDL-python validates fields as unsigned. For signed values (e.g. 16-bit IQ),
convert with helpers:

```python
def _to_unsigned(val, bits=16):
    return val & ((1 << bits) - 1)

def _to_signed(val, bits=16):
    half = 1 << (bits - 1)
    return val - (1 << bits) if val >= half else val
```

Writing a negative value directly raises
`ValueError: value ... must be greater than or equal to 0`. Wrap with
`_to_unsigned()`.

## Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| `make driver` runs `... _regmap.rdl` (empty name) | Duplicated/empty `RDL_FILE` in `rdl/Makefile`. Fix the heredoc in `create_ip.sh` (`<< 'EOF'`, no backslashes, remove duplicate line). |
| `make driver` runs `... ip_regmap.rdl` | `IP_NAME` uses two `dirname` calls -> resolves to `ip`. Use a single `dirname`. |
| `make ... gen: missing separator` | Recipe lines use spaces instead of TABs. Use the `@@TAB@@` + `sed` trick. |
| `ModuleNotFoundError: No module named '<ip>_regmap_pkg'` | Package not generated. Run `make driver IP=<name>`; ensure `conftest.py` adds `rdl/` to `sys.path`. |
| `TypeError: callbacks ... NormalCallbackSet` | Too few callbacks. Provide all four (`read`, `write`, `read_block`, `write_block`). |
| Import of the model class fails (hash-suffixed name) | Don't import `<ip>_neg_0x..._cls`. Import the clean alias `RegModel` from `<ip>_regmap_pkg.reg_model`. |
| Generated regblock SV conflicts with the custom AXI slave | You left `--hdl` in `gen` for a strategy-2 IP. Remove `--hdl`; keep `--python` (+ `--html`). |
| Driver works in dev but not on the board | Package not deployed, or VLNV != `bindto`. Re-run `make driver`, commit the symlink and `rdl_pkgs/<ip>_regmap_pkg`, redeploy, verify VLNV. |
| `AttributeError: 'DefaultIP' object has no attribute 'regs'` | PYNQ bound the IP to the generic `DefaultIP`: the driver module is not in `qick_lib/qick/drivers/` (run `make driver IP=<name>`), failed to import (look for the `IP driver ... could not be imported` warning), or its `bindto` does not contain the IP's VLNV. |
| Warning `IP <name> (qick:ip:...) has no QICK driver bound` | Same as above, reported by `QickSoc` at start-up. |
| `ModuleNotFoundError: No module named '<ip>_regmap_pkg'` on the board | `qick_lib/qick/rdl_pkgs/<ip>_regmap_pkg` is not in the clone (not committed, or dropped by the root `_*` ignore rule). |
| `RuntimeError: No tProcessor found` | The firmware has no tProc: use `QickSoc(bitfile, no_tproc=True)`. |
| An output that only updates the first time you write it | A strobe register left high: the RTL wants an edge. Pulse it. |
| `make driver` output differs on every run | Generation without `PYTHONHASHSEED=0` (the Makefile sets it; a hand-run `rdl_tools.py` does not). |

## Lessons Learned (summary)

- Use a **faithful BRAM model** (synchronous, registered, write-first like
  `bram_tdp`) in RTL testbenches — idealized combinational models hide real
  read-latency bugs.
- AXIS writers must advance address/pipeline only on **accepted beats**
  (`tvalid && tready`), not on `tvalid` alone — otherwise the first beat is lost
  when `tvalid` leads `tready` at transaction start.
- Use **indexed part-selects** (`[base +: WIDTH]`) with a variable base; xsim
  rejects `[msb:lsb]` when the bounds depend on a loop variable.
- In testbenches, do not sample combinational outputs of **single-cycle states**
  right after `wait_state`; use a concurrent `fork` monitor or settle a cycle.
- Synchronize multi-transaction tests on **real state** (`tready`, `busy`), not
  on fixed `repeat` margins.
- For PeakRDL: import the **clean aliases** (`RegModel`, `Simulator`), provide
  **four callbacks**, and treat the generated `_*_sim_test_base.py` as the
  source of truth for the API.
- Keep `axi_slv_tprocv1` for IPs that need a memory window + handshake; the RDL
  is for the **driver layer and docs only** in that case (no `--hdl`).
- **Fix RTL bugs in `rtl_lib/`, document them in the module header.** Case
  study: SG-v6 amplitude fix — the register map even grew STATUS/CTRL registers
  to expose the new ±MAXV saturation to software.
- **A single driver can bind multiple IP versions** (`AxisSignalGen` -> v4/v5/v6).
  When you change one IP's RTL/registers, re-check the shared driver against the
  others.
